2.2.2. Value Types and Reference Types

In the Java language, an instance of a non-primitive type has a well-defined object identity unique to the instance and is passed by reference, meaning that assignment of the instance to a field, local variable, or method parameter, followed by later access to the assigned value, preserves the identity of the instance.

In general, operations performed by a persistence provider are not required to preserve the object identity of a value stored in an attribute of an entity. The provider is permitted to modify the value held in the attribute to a new value with a distinct object identity. But such modifications never alter the persistent representation of the entity because the Java object identity of a value held in an attribute is never part of the persistent state of the entity.

In particular:

  • A basic type, an embeddable class, or any collection type is considered a value type, and the provider is not required to respect the integrity of shared references to an instance of such a type. If multiple fields referenced the same instance of a value type when an entity was made persistent, those fields may hold references to distinct instances of the value type when the entity is reloaded from the database.

  • An entity type is considered a reference type, and, instead of object identity, every managed instance of an entity type has a well-defined persistent identity. The persistence provider must respect its persistent identity by:

    • preserving the persistent identity of an instance when it is made persistent and then later reloaded from the database, and

    • ensuring that, within a single persistence context, at most one object represents the state of each distinct persistent identity, thus preserving the integrity of shared references to entities belonging to the given persistence context.

    This requirement notwithstanding, the container is permitted to introduce an indirection or proxy between the object which represents the state of an entity and attributes which hold references to the entity. Thus, object identity might still not be respected in a strict sense, not even for a reference type.
